## 修正一覧

### R18a-3 P0-2 — ray firewall script で `Any` 公開を throw

| | |
| --- | --- |
| 影響 | 旧コードは `RemoteAddress="Any"` / `0.0.0.0/0` を `Write-Warning` のみで通過させ New-NetFirewallRule を実行。Ray GCS / dashboard / worker は **無認証** で cloudpickle RCE 可能 (P0-2)。public expose を実装で阻止できていなかった |
| ファイル | `shuttlescope/scripts/fix_ray_firewall.ps1` |

**修正方針**:
- `Any` / `0.0.0.0/0` / `::/0` / `*` 検知時は `throw` で即停止。
- どうしても必要な場合は `SS_RAY_FIREWALL_FORCE_PUBLIC=1` を別 env として明示的に set した時のみ警告を出して継続。レビュー時に env 名で気付ける形にした。

### R18a-3 P1-3 — cloudflared `noTLSVerify: true` 削除

| | |
| --- | --- |
| 影響 | origin が `http://localhost:8765` の間はフラグ自体は no-op だが、運用者が origin を `https://...` にコピペ改変した瞬間に edge↔origin 間の MITM を黙認する地雷化 |
| ファイル | `shuttlescope/infra/cloudflared/config.yml` |

**修正方針**: 全 ingress から `noTLSVerify: true` を撤去。コメントで「origin を https に変えた場合に明示追記する」旨を残す。

### R18a-1 P2-1 — mirror-broadcast に sender frame gate

| | |
| --- | --- |
| 影響 | 将来 webview / sub-frame / 別 BrowserWindow を導入したときに、信頼境界外の sender が任意 mirror-message を全 window に注入できる経路。`relaunch-app` には同等 gate があるが mirror-broadcast に無かった |
| ファイル | `shuttlescope/electron/main.ts` |

**修正方針**: `event.senderFrame?.parent != null` で sub-frame を弾き、`event.sender.id !== mainWindow.webContents.id` で別 BrowserWindow を弾く。

### R18a-1 P2-3 — app://video/{token} の `Range` ヘッダ書式 validation

| | |
| --- | --- |
| 影響 | renderer から渡された `Range: bytes=0-99999999999999` が無検証で backend にフォワードされ、memory amplification の primitive |
| ファイル | `shuttlescope/electron/main.ts` |

**修正方針**: `^bytes=\d{1,12}-\d{0,12}$` の正規表現で書式を確認、不適合は drop して warn ログ。

### R18a-2 P2-1 — `cleanup_expired_revoked_tokens` 定期 GC

| | |
| --- | --- |
| 影響 | 起動時のみ cleanup していたため、長時間稼働で `revoked_tokens` が膨らみ毎リクエストの `_is_token_revoked` が線形劣化 |
| ファイル | `shuttlescope/backend/main.py` (lifespan) |

**修正方針**: lifespan に `_revoked_tokens_gc_loop` を追加。1 時間毎に `cleanup_expired_revoked_tokens()` を `asyncio.to_thread` 経由で実行。yield 後 cancel/await。

### R18a-2 P2-2 — WS operator の JWT 60s 周期再検証

| | |
| --- | --- |
| 影響 | accept 時に 1 度だけ JWT 検証する設計のため、admin が当該ユーザの token を mass_revoke / 個別 revoke / role 降格しても WS は切れず、operator 権限を保持し続けてしまう |
| ファイル | `shuttlescope/backend/ws/camera.py` |

**修正方針**: receive ループに 60s 毎の再検証を挟む。`?token=` が空 (loopback ALLOW_LOOPBACK_NO_AUTH 経路) では skip。検証失敗時は 4401 で close。

### R18a-2 P2-3 — 24h legacy token grace の mfa_pending bypass

| | |
| --- | --- |
| 影響 | iss/aud/token_use いずれも持たない pre-iss/aud token は 24h grace で許容されるが、`get_auth()` が見ているのは `token_use=="mfa_pending"` のみ。 legacy token に `role=="mfa_pending"` があった場合は無検査で通る |
| ファイル | `shuttlescope/backend/utils/jwt_utils.py` |

**修正方針**: legacy grace 経路で `payload.get("role") == "mfa_pending"` を明示的に reject。

### R18a-2 P3-1 — `ws_require_auth` の IPv6 normalize

| | |
| --- | --- |
| 影響 | dual-stack listener で内部接続が `::ffff:127.0.0.1` (IPv4-mapped IPv6) として現れた場合、文字列 set 比較で loopback 判定が外れて `?token=` 経路にフォールバックする cosmetic な不整合 |
| ファイル | `shuttlescope/backend/main.py` (`_ws_require_auth`) |

**修正方針**: `control_plane._normalize_ip` を呼び出して比較前に IPv4 形に正規化する。
