# Round 258 R42 to R45 — 多層 deception + escalation + 永遠の迷路

## 概要

R40-R41 で state-level defense (PG 権限剥奪 + canary endpoint + 自動 ban) を
入れた後、R42-R45 で「攻撃者を放置して時間と帯域を奪い、行動ログから将来の
防御を強化する」方針 (= D 戦略) に振り切った。

設計の柱:

1. **静的 honeytoken** (`.env.example` / DB seed / フロント bundle) を分散配置し、
   攻撃者が取得した値の **provenance** (どこから抜いたか) を request 時に特定する
2. **動的 staged honeytoken** — 一度怪しい挙動を踏んだ IP の正常 response に
   餌を混入させ、再利用したら catch する
3. **decoy maze** — 偽 admin / 偽 .env / 偽 backup / catch-all で永遠の迷路を作り、
   crawler を再帰的に泳がせる
4. **VPN/Tor/CGNAT セーフ ban** — ASN ベースで永久 block を絶対しない政策
5. **TTL 付き escalation 自動 ban** — 10/100/1000 回の閾値で 30s/600s/3600s ban、
   超過後は自動 unban

### Staged honeytoken (動的)

- `backend/utils/staged_honeytoken.py`:
  - `mark_suspicious(ip, reason)` — 24h TTL の in-memory state
  - `is_suspicious(ip)` — middleware 参照用
  - `maybe_inject_lure_into_json_bytes(body)` — JSON dict ルートに

- `LURE_TOKEN` を `HONEYTOKENS` 辞書に登録 (provenance=`staged_in_response`)
- `backend/tests/test_staged_honeytoken.py` — 7 件 (mark/inject/envelope/skip 系)

### 検証

- envelope `{"success": True, "data": {"x": 1}}` の両層に lure 混入されることを

- array root / oversized / 非 JSON は skip されることを確認
- LURE_TOKEN が HONEYTOKENS dict に登録済みで、攻撃者が再利用すると R42

- 本番デプロイ後、loopback IP が canary 経由で suspicious 認定され

## R44 — VPN/Tor/CGNAT セーフ ban + Decoy maze + 行動ログ

### CF ban policy (誤 ban 防止の本丸)

- `backend/utils/cf_ban_policy.py`:
  - `_VPN_TOR_ASNS` 11 件 (Mullvad / Proton / NordVPN / Surfshark / PIA /
    IPVanish / ExpressVPN / Windscribe / CyberGhost / CF WARP)
  - `_MOBILE_CGNAT_ASNS` 9 件 (KDDI au / NTT docomo / SoftBank / NTT OCN /
    Comcast / AT&T Mobility / T-Mobile US / Rostelecom)
  - `_CLOUD_VPS_ASNS` 12 件 (AWS / Azure / GCP / Hetzner / DO / OVH / Vultr /
    Linode / Akamai / Scaleway)
  - `decide_cf_mode(ip, asn, confidence)` で final mode 決定:
    - vpn_tor → 常に `managed_challenge` (永久 block 絶対 NG)
    - mobile_cgnat → critical でも `challenge` 止まり
    - cloud_vps → critical/medium で `block`、low は `challenge`
    - unknown → 保守的に `challenge` 止まり (block しない)
    - loopback → `whitelist` (何もしない)
  - `load_tor_exit_list_from_file()` — `SS_TOR_EXIT_LIST_PATH` 環境変数経由で
    `check.torproject.org/exit-addresses` ファイルをロード、該当 IP は ASN
    関係なく `managed_challenge`

### Decoy maze

- `backend/routers/decoy_maze.py`:
  - 偽 admin login: `/admin`, `/admin/login`, `/administrator`, `/admin.php`,
    `/wp-login.php`, `/wp-admin/`, `/phpmyadmin/`, `/manager/html`, `/cpanel` 等
  - POST `/admin/login` は 60% 成功 / 40% 失敗 のランダム遷移
  - 偽 dashboard `/admin/dashboard` (8 リンク: users / db/export / backup /
    config / secrets / workers / tokens / legacy)
  - 偽 .env `/.env`, `/.env.production`, `/.env.local`, `/.env.bak`,
    `/config/.env`, `/app/.env`, `/backup/.env` 全部 honeytoken 入り
  - 偽 secrets / tokens / workers JSON エンドポイント
  - 偽 `/backup.sql`, `/.git/config`, `/db.sqlite` ダミー応答
  - 偽 server header `Server: Apache/2.4.41 (Ubuntu)` + `X-Powered-By: PHP/7.4.33`
  - JP/EN ミックスの挑発メッセージ (`_TAUNTS` から HTML コメントとして埋め込み)
- `backend/main.py` に decoy_maze router を canary router の直後に register

## R45 — 「永遠に泳がせる」 + TTL 付き escalation 自動 ban

### Escalation policy

- `backend/utils/escalation_policy.py`:
  - kind 別 hit カウンタ (IP×kind の独立カウント)
  - 閾値到達時のみ `{ttl_sec, confidence}` を返す:
    | kind         | threshold | ttl_sec | confidence |
    |--------------|-----------|---------|------------|
    | honeytoken   | 10        | 30      | critical   |
    | honeytoken   | 100       | 600     | critical   |
    | honeytoken   | 1000      | 3600    | critical   |
    | canary       | 30        | 60      | medium     |
    | canary       | 300       | 600     | medium     |
    | decoy_maze   | 500       | 60      | low        |
    | decoy_maze   | 3000      | 600     | low        |
  - 同 threshold の再評価では re-fire しない (一度跨いだ threshold を `_last_tier`
    で記憶)
  - `reset_ip(ip)` で手動 unban 時のカウンタリセット

### TTL 付き CF ban

- `canary._trigger_cf_auto_ban` に `ttl_sec` 引数追加
- 成功時 `threading.Timer(ttl_sec, _do_cf_unban_by_id)` で TTL 経過後に
  CF rule を DELETE
- CF rule notes に `expires=<unix_ts>` を含め、process 再起動で Timer が
  消えても運用者が CF dashboard で残骸 rule を notes フィルタで掃除可能
- unban 時に `_recent_bans` dedup 解除 (次回 escalation で再 ban できるよう)

### 既定動作の切替

- canary hit / honeytoken hit / decoy_maze hit の全てを escalation 経由に変更
- kill-switch: `SS_DISABLE_AUTO_CF_BAN=1` で全 ban 経路 OFF

### Decoy maze 強化

- 同時 tarpit cap `_MAZE_MAX_CONCURRENT = 128` (self-DoS 防止)
- catch-all `GET/POST/PUT/PATCH/DELETE /admin/{rest:path}` `/internal/{rest:path}` —
  何叩いても 200、Accept ヘッダで JSON か HTML を自動判別
- HTML 応答内に 4-8 個のランダム生成リンク (config / settings / users /
  tokens / secrets / backup / export / dump / logs / audit / v1-v3 / internal /
  legacy / archive / raw / debug / metrics から random.sample)
- 単発「美味しそう」path 22 種: `/server-status`, `/.aws/credentials`,
  `/.ssh/id_rsa`, `/id_rsa`, `/swagger.json`, `/api-docs`, `/graphql`,
  `/graphiql`, `/console`, `/jolokia`, `/actuator/heapdump`, `/druid/v2`,
  `/solr/admin`, `/elasticsearch`, `/kibana`, `/grafana`, `/jenkins` 等
- `/.aws/credentials` は AWS credential 形式で honeytoken 配置、
  `/.ssh/id_rsa` は OpenSSH private key 形式で fake content

### 検証

- 9 回までの honeytoken hit で `record_hit_and_decide` が None を返し、10 回目で
  `ttl_sec=30` を返すことを smoke test で確認
- 11-99 回の間は再 fire しないことを確認
- 100 回目で `ttl_sec=600` に昇格することを確認
- canary 30 回で `ttl_sec=60` が return されることを確認
- kind 違いカウンタが完全独立であることを確認
