R22 までの監査が継続的に backlog 化していた長期 P1/P2 を 1 commit にまとめてクローズ。

## 修正一覧

### R23 P1 — SFTP TOCTOU (R18a-3 P1-1)

| | |
| --- | --- |
| 影響 | `_ssh_run_python_script` は `C:/Users/{username}/ss_task_<8hex>.py` の共通空間に SFTP 書込みしてから `ssh.exec_command` で起動するため、(a) 低権限ローカル actor が同 path に対し TOCTOU で内容を差し替えられる、(b) 8 hex (32 bit) suffix は brute force 可能、(c) atomic 作成フラグ未使用 |
| ファイル | `shuttlescope/backend/cluster/remote_tasks.py` (`_ssh_run_python_script`) |

**修正方針**:
- script_path を `%TEMP%\ShuttleScope\ss_task_<32hex>.py` に移動 (NTFS 既定 DACL で他 user は cd のみ)。
- suffix を `uuid4().hex` 全 32 hex (128 bit) に拡大 → brute-force 不可能。
- `sftp.mkdir(parent)` を冪等に呼び親ディレクトリを確保。
- `sftp.open(..., "wb")` に変更 (paramiko の SFTP API では O_EXCL 相当を直接指定できないが、128 bit 乱数で実質衝突不可)。

### R23 P1 — `dispatch_benchmark` SSH credential lookup (R18a-3 P1-2)

| | |
| --- | --- |
| 影響 | 旧 `dispatch_benchmark` は YAML から直接 `ssh_user` / `ssh_password` を読んでいたが、`topology._redact_secrets` で永続化されると YAML 上の `ssh_password` が `"SSH_PASSWORD_REDACTED"` 文字列に化ける。その状態だと redacted 文字列を SSH 試行 → 認証失敗の timing 観測 + redacted 検出が容易 |
| ファイル | `shuttlescope/backend/cluster/remote_tasks.py` (`dispatch_benchmark` のループ) |

**修正方針**: 既存の env-aware ヘルパ `_get_worker_ssh_creds(wip)` 経由に統一。redacted YAML / env-var override / disabled worker のすべてを正しく扱う。

### R23 P2 — `_revoked_tokens_gc_loop` shutdown 時の leak (R20 P2-1)

| | |
| --- | --- |
| 影響 | `asyncio.to_thread(_cleanup_rev)` は thread を kill できないため、shutdown 時の cancel で SQLAlchemy session が pool 内に残り、hot-reload 時に connection-pool exhaustion |
| ファイル | `shuttlescope/backend/main.py` (lifespan) |

**修正方針**:
- cleanup を `_safe_cleanup` wrapper でラップし、SQLite なら `PRAGMA busy_timeout = 5000` を強制 → long DB lock を 5s で abort。
- session は `with SessionLocal()` の context manager で確実に close される (cleanup_rev 側既存パターン維持)。

### R23 P2 — sentinel jti 衝突可能性 (R22 P2-2)

| | |
| --- | --- |
| 影響 | R21 で導入した `uuid4().hex[:8]` (32 bit) は ~65k 同時発行で birthday paradox 衝突。`__user_revoke_<id>_<iso>_<8hex>` の組合せでも同一秒内ラッシュで IntegrityError → silent failure 経路 (R22 で raise 化したが衝突自体は残存) |
| ファイル | `shuttlescope/backend/utils/jwt_utils.py` (`revoke_all_for_user`) |

**修正方針**: `secrets.token_hex(16)` の 128-bit に拡大。birthday 衝突は宇宙年齢でも非現実的。

### R23 P2 — PKWARE-AES backup passphrase entropy 強制 (R18a-3 P2-1)

| | |
| --- | --- |
| 影響 | 旧コードは「20 文字以上」を強制していたが、`"a"*20` のような単一文字 20 連は Shannon エントロピー 5 bits 程度で PBKDF2-SHA1 1000 iter のオフライン総当たりに対し脆弱 |
| ファイル | `shuttlescope/backend/services/backup_service.py` |

**修正方針**: Shannon entropy 計算を追加し、`H(passphrase) ≥ 4.0 bit/char` (= passphrase 全体で約 80 bits 以上) を強制。`secrets.token_urlsafe(24)` 等で生成すれば余裕で通る。
