# Round 258 R17 — R16 regression hotfix + 残 P1/P2/P3

## 概要

Round 258 R16 (commit fd69298) で導入した security 強化のうち、**2 件が production-breaking regression** だったことを R17a 監査が独立に検出。
本 R17 では当該 2 件 (NEW-1, NEW-2) を P0 hotfix し、同時に R17a が指摘した残 4 件 (NEW-3 P2, NEW-4 P1, NEW-5 P2, NEW-6 P3) も同 commit で塞ぐ。

監査スタイルは R7 以降踏襲している「**R(N) で fix → R(N)a で independent agent が裏取り → R(N+1) で残対応**」という cycle。今回の R17 は cycle が想定通り回ったことを示す事例でもある (= 自己レビューで見落とした production breakage を裏取りで救えた)。

## 修正一覧

### NEW-1 P0 — `useServerSideRecording.ts` chunk retry を完全撤去 → データ損失

| | |
| --- | --- |
| 影響 | sender (試合中の選手 / iPad) の MediaRecorder upload が **transient な 5xx / network error 一発で chunk 永久喪失**。試合映像に穴が空く |
| ファイル | `shuttlescope/src/hooks/session/useServerSideRecording.ts` |
| Round | R16 fd69298 で `localStorage` 経由 retry を削除した際、retry path 全体を消してしまった |

**修正方針**:
- メモリ上の `Map<chunkIndex, Blob>` (= `pendingRef`) に失敗 chunk を積む。**localStorage には書かない** (R16 F-2 が塞いだ DoS / XSS 経路を温存)。
- 容量上限 `MAX_PENDING_CHUNKS = 20` (~160 MB)。超過時は古い順に drop し `errorMsg` に明示。
- `setInterval(flushPending, 15s)` で再送。同時実行は `retryInFlightRef` で 1 つに制限。
- `stop()` で finalize 前に明示 `flushPending()` 一発、その後 timer を解放。
- 4xx は積まない (auth/validation 失敗は retry しても無駄)。5xx と fetch throw のみ retry 対象。

### NEW-2 P0 — CSP allowlist で `http://localhost:*` を全削除 → packaged Electron broken

| | |
| --- | --- |
| 影響 | `npm run build` 後の packaged Electron が起動直後に backend (`http://localhost:8765`) に到達できず、全機能停止 |
| ファイル | `shuttlescope/electron/main.ts` |
| Round | R16 fd69298 で `http://localhost:*` ワイルドカードを「ローカル平文のすべて」と判定して削った。renderer (`file://`) → child Python (`http://localhost:8765`) の正規経路まで死亡 |

**修正方針**:
- `_PROD_CONNECT_ALLOWLIST` に `http://localhost:8765` と `ws://localhost:8765` を **port 限定** で再追加。任意 port を許す `localhost:*` には戻さない。
- 8765 は `electron/main.ts` の child Python launcher が固定で使っている port なので、その定数 1 つだけを allowlist する。

### NEW-3 P2 — operator relay の `_id_ok` lambda が Unicode-aware で homoglyph bypass

| | |
| --- | --- |
| 影響 | `target_participant_id` に `０`（U+FF10 fullwidth zero）等の Unicode 数字を仕込むと `str.isalnum()` が True を返し、operator が ASCII の通常 ID と区別困難な dict key で内部 state を膨らませる |
| ファイル | `shuttlescope/backend/ws/camera.py` |

**修正方針**:
- lambda + `str.isalnum()` を `re.compile(r"^[A-Za-z0-9_-]{1,64}$").fullmatch` に置換。ASCII のみ許容。
- 上部 import に `import re` を追加。

### NEW-4 P1 — mirror-broadcast の `<video src="https://...">` allowlist が generic 過ぎ

| | |
| --- | --- |
| 影響 | renderer XSS 後、別 window の `<video>` を任意の `https://evil.example.com/xx.mp4` 再生に誘導でき、被害者の IP/UA を任意ドメインに送る covert exfil |
| ファイル | `shuttlescope/electron/main.ts` (`_isAllowedMirrorVideoSrc`) |

**修正方針**:
- `https://` 全許容を撤去。`new URL()` で parse して `protocol === 'https:'` を確認した上で、`hostname` を `_MIRROR_HTTPS_HOSTS = {app.shuttle-scope.com, www.shuttle-scope.com, shuttle-scope.com, cdn.shuttle-scope.com}` の正確一致だけ許す。
- ASCII 制御文字 / `\x00-\x1f\x7f` を含む URL は早期 reject (URL parser 抜け対策)。
- `localfile:///`, `app://video/`, `blob:` は従来通り。

### NEW-5 P2 — `0027_idempotency_cache_columns.py` の NOT-NULL 昇格 idempotent 化

| | |
| --- | --- |
| 影響 | Phase 2 で NOT NULL alter が一度失敗した DB に対して再実行すると、Phase 1 の UPDATE backfill が `if "X" not in cols:` 条件でスキップされ、永久に詰む |
| ファイル | `shuttlescope/backend/db/migrations/versions/0027_idempotency_cache_columns.py` |

**修正方針**:
- Phase 1 を 1a (`add_column` のみ条件付き) と 1b (`UPDATE ... WHERE X IS NULL` を**無条件**実行) に分離。
- 1b は WHERE 条件で副作用ゼロを保証 → 何度実行しても同じ結果。
- これにより Phase 2 の NOT NULL alter は前回失敗からの復旧再実行でも常に通る。

### NEW-6 P3 — sweeper prefix regex の tighten

| | |
| --- | --- |
| 影響 | `startsWith('__ss_pending_upload_')` は緩く、将来別目的で同 prefix を使う legitimate key を誤って sweep する可能性 |
| ファイル | `shuttlescope/src/hooks/session/useServerSideRecording.ts` (`_sweepStaleUploadQueue`) |

**修正方針**:
- 正規表現 `^__ss_pending_upload_[A-Za-z0-9_-]{1,128}$` で prefix 直後の suffix 形式を厳格化。
- 旧フォーマット `__ss_pending_upload_<uploadId>_<chunkIndex>` / `__ss_pending_upload_<chunkIndex>` の双方をカバー。

## 検証

### Frontend build
- `NODE_OPTIONS=--max-old-space-size=16384 npm run build` 成功 (vite 7.3.2 / electron-vite, 2911 modules transformed, ✓ built in 9.15s)。

### Backend tests
- `python -m pytest backend/tests/test_websocket_signaling.py backend/tests/test_idempotency_persistence.py` (+ 関連)。`re` import / `_id_ok` 入れ替え後の signaling/idempotency 経路が緑。

### Manual (本番デプロイ後)
- packaged Electron を `npm run start` ではなく **build artifact** で起動し、renderer から `/api/health` の到達を確認 (NEW-2 regression が再発しないことの検証)。
- sender ページで MediaRecorder を 30s 録画 → 途中で backend を `kill -STOP` → 30s 後に `kill -CONT` → pending chunk が flush され total upload が連番完成することを確認 (NEW-1)。
- mirror-broadcast IPC で `<video src="https://evil.example.com/x.mp4">` を payload にした raw IPC を流し、`[mirror-broadcast] rejected: unsafe video src scheme` が出ることを確認 (NEW-4)。
