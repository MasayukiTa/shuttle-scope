# Round 258 R25 — R24 audit P1/P2/P3 + 自身 R22 cache bug

## 概要

R24 (f3b4f7c) を 1 体の独立 agent で再監査。R22 で導入した per-user revoke cache の
**arithmetic bug** を発見 (P2-1) — `now - (TTL - 2.0)` という past timestamp を
書いていたため cache が常に stale で DB 連打、R22 の主目的だった DoS 抑制が **完全に
no-op** だった。本 R25 で完全修正。

加えて R24 の listener 登録タイミング問題 (P1-1) / SFTP TEMP resolve deadlock (P1-2)
/ saveRecordedVideo 基本ファイル名 strip (P2-2) / operator token rotation (P3-3) を
同梱。

- R25 P2-1 (own-bug): jwt_utils.py per-user cache の timestamp を `(now, ts)` に修正
- R25 P1-1: SQLite busy_timeout listener を db/database.py の engine 構築直後に移動
- R25 P1-2: SFTP TEMP resolve を select-loop + 5s wall-clock で hang 防止
- R25 P2-2: saveRecordedVideo の defaultFilename を path.basename + control char strip
- R25 P3-3: sessions regenerate-password で operator_token も同時に rotate
- (継続) R22 P3-1 Punycode 注釈 / R22 P3-2 reverify jitter は別 commit (a03f48c) で済

## 修正一覧

### R25 P2-1 (R22 self-introduced) — fail-closed cache が常に stale

| | |
| --- | --- |
| 影響 | R22 で「2 秒だけ cache する」意図で `now - (TTL - 2.0) = now - 3.0` を書いたが、cache 取り出し時 `now - cached[0]` は即座に 5+ s となり TTL=5s を超え、cache が **常に stale 扱い** で DB に連打。R22 の DoS 抑制が完全に no-op。R22 の audit 報告で動作が直っているように書かれていたが、実装は intent と齟齬 |
| ファイル | `shuttlescope/backend/utils/jwt_utils.py` |

**修正方針**: `(now, ts)` を素直に書き、最初の 5s 間 cache hit する正しい挙動にする。

### R25 P1-1 — engine connect listener が pre-warmed pool に当たらない

| | |
| --- | --- |
| 影響 | R24 で main.py の lifespan 内に登録した SQLite busy_timeout listener は、bootstrap_database() が lifespan より先に動き pool に pre-warm 接続を作るため、後発の listener は既存接続には反映されない race。busy_timeout 5000 が実際には未適用で OperationalError 経路 |
| ファイル | `shuttlescope/backend/db/database.py` (engine 構築直後 listener) / `shuttlescope/backend/main.py` (旧 listener 撤去) |

**修正方針**: 既存の `_sqlite_pragma_on_connect` listener (engine 構築直後の `@event.listens_for`) に `PRAGMA busy_timeout=5000` を追加。最初の checkout から確実に適用される。lifespan 側の listener 登録は撤去。

### R25 P1-2 — SFTP TEMP resolve deadlock on PowerShell-default hosts

| | |
| --- | --- |
| 影響 | OpenSSH on Win10/11 で default shell が PowerShell に変更されているケースでは `cmd /c echo %TEMP%` が channel close されず数秒 hang し、`_stdout.read()` は `settimeout(5)` を honor しない (paramiko ChannelFile 仕様)。Cluster benchmark dispatch が直列に 5s × N hang する soft DoS |
| ファイル | `shuttlescope/backend/cluster/remote_tasks.py` (`_ssh_run_python_script`) |

**修正方針**: `chan.settimeout(0.0)` non-blocking + `select.select` で 5s wall-clock budget の polling loop に書換。`exit_status_ready() and not recv_ready()` で完了検知。

### R25 P2-2 — saveRecordedVideo の defaultFilename path traversal

| | |
| --- | --- |
| 影響 | renderer 由来 `defaultFilename` をそのまま `dialog.showSaveDialog` の `defaultPath` に渡していた → npm 依存先の supply-chain 経由で `defaultFilename = "../../.ssh/authorized_keys"` を渡されると user profile 外を初期 path にして、enter で押下 race |
| ファイル | `shuttlescope/electron/main.ts` |

**修正方針**: `path.basename` でフォルダ部除去 → 制御文字 (0x00-0x1F + 0x7F) strip → 200 char 切り詰め → `dialog.showSaveDialog` に渡す。後段の realpath jail (R21/R22) と組み合わせて二重防御。

### R25 P3-3 — sessions `regenerate-password` で operator_token を rotate しない

| | |
| --- | --- |
| 影響 | 旧コードは session password だけ更新し operator_token は維持。漏洩した operator token を持つ actor が LAN/リモートから operator API を呼び続けられた |
| ファイル | `shuttlescope/backend/routers/sessions.py` |

**修正方針**: `_generate_operator_token()` で新 token を発行し `_operator_tokens[code]` を上書き、レスポンスに含めて返す。
