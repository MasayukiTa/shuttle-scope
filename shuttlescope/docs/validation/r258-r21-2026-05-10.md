# Round 258 R21 — R20 self-introduced P0 + R7-R19 leftovers + 残 backlog

## 概要

R20 (afc7752) を 1 体の独立 agent で再監査。R20 で導入した `revoke_all_for_user` に
**P0 silent failure** が見つかった (sentinel UNIQUE collision で例外、caller が握り潰し、
access token 失効が走らない)。さらに R7-R19 の長期 backlog から 8 件を同 commit にまとめた。

- R21 P0-1: `revoke_all_for_user` sentinel uniqueness + caller の silent except 撤去
- R21 P1-1: per-user revoke cache の fail-closed
- R21 P1-2: save-recorded-video の Windows realpath jail を allow-list 化 (`\\?\` / UNC bypass 閉鎖)
- R21 P1-3: WS operator reverify を `asyncio.to_thread` に逃がす + except narrow
- R21 P1-4: user_update (role/password/pin/username) でも `revoke_all_for_user` 呼ぶ
- R21 P3-3: `_FORCED_STRIP_COLUMNS` に MFA / role / is_active 系を追加
- R18a-3 P2-2: WOL は `is_private` 限定 (multi-tenant subnet leak 阻止)
- R18a-3 P2-3: `_FORCED_STRIP_COLUMNS` に `pkid`/`external_id`/`device_id`/`session_id` 等の future-aliasing を追加
- R18a-3 P3-1: `worker.py` の pid_str を ASCII-only に (Unicode digit reject)
- R18a-3 P3-3: `install_supervisor.ps1` の cmd リダイレクトを Windows 形式 `>nul 2>&1` に修正
- R18a-2 P3-2: `is_loopback_request` の dev-mode blank/testclient grant を ENVIRONMENT が明示的に dev/test の時だけに限定
- R18a-1 P3-1: sweeper の module-level `_didSweepStaleUploadQueue` flag で多重 mount 抑止
- R18a-1 P3-2: `_validateUserUrlForCapture` で数字始まり hostname を全 reject (octal / hex / 1進 IPv4 異形対策)

## 修正一覧 (重要箇所)

### R21 P0-1 — `revoke_all_for_user` の silent failure

| | |
| --- | --- |
| 影響 | R20 で導入した sentinel `__user_revoke_<user_id>_<isoformat>` は RevokedToken.jti UNIQUE 制約で衝突 (2 回目以降の concurrent change_password で IntegrityError) → caller が `except Exception: warning` で握り潰し → password 変更だけ成功 / access token 失効が走らない 15 min 残存窓 |
| ファイル | `shuttlescope/backend/utils/jwt_utils.py` (`revoke_all_for_user`) / `shuttlescope/backend/routers/auth.py` (change_password / admin_reset_password) |

**修正方針**:
- sentinel に `uuid.uuid4().hex[:8]` を suffix → 衝突不可能化
- caller 側で raise を維持 (silent except を撤去) → DB 失敗時は HTTP 500 で素直に止める

### R21 P1-2 — `save-recorded-video` の Windows realpath jail bypass

| | |
| --- | --- |
| 影響 | R19 の deny-list (windir / Program Files / ProgramData) は `\\?\C:\Windows\...` extended-length prefix / UNC `\\server\share\` / drive root の C:\autoexec.bat 等を全て通していた |
| ファイル | `shuttlescope/electron/main.ts` |

**修正方針**:
- deny-list → **allow-list**。`app.getPath('documents'/'downloads'/'videos'/'desktop')` 配下のみ書込可能。
- `\\?\UNC\...` / `\\server\share\...` は別途明示 reject。
- realpath 解決後の正規化 path を `path.sep` 付き prefix match で照合。

### R21 P1-3 — WS reverify が event loop を block + CancelledError 握り潰し

| | |
| --- | --- |
| 影響 | R20 の `verify_token` は同期 SQLAlchemy query を event loop thread 上で実行 → DB 遅延がそのまま全 WS / HTTP 停滞。さらに `except Exception` で `asyncio.CancelledError` まで吸収して shutdown が hang |
| ファイル | `shuttlescope/backend/ws/camera.py` |

**修正方針**:
- `await asyncio.to_thread(verify_token, _saved_token)` で別 thread に逃がす
- except を `(JWTError, OSError)` に narrow、`CancelledError` は `raise`

### R21 P1-1 — per-user revoke cache の DB 失敗時に negative cache 書く問題

| | |
| --- | --- |
| 影響 | R20 実装は DB 例外時に `_USER_REVOKE_CACHE[user_id] = (now, None)` を書いていた。直後に admin が emergency revoke を打っても 5s TTL の間 cache が None (= 失効無し) を返し、当該 user の旧 token が valid と判定される 5 秒の DoS 経路 |
| ファイル | `shuttlescope/backend/utils/jwt_utils.py` |

**修正方針**: DB 失敗時は cache に書かず、return value を **1 年後 timestamp** にして fail-closed (= iat < future_ts は常に成立 → 全 token reject)。

### R21 P1-4 — user_update 経由の role 降格で access token 残存

| | |
| --- | --- |
| 影響 | `change_password` / `admin_reset_password` のみ `revoke_all_for_user` を呼んでおり、admin が compromised user を `analyst` に demote しても 15 min は role=admin の access token で活動可能 |
| ファイル | `shuttlescope/backend/routers/auth.py` (update_user) |

**修正方針**: `body.model_dump(exclude_unset=True)` に `role` / `password` / `pin` / `username` のいずれかが含まれる場合は `revoke_all_for_user(target_id)` を呼ぶ (silent failure 禁止 / 500 で raise)。

### R18a-3 P2-2 — WOL global broadcast leak

| | |
| --- | --- |
| 影響 | `wake_worker` は `worker_ip` の解析失敗時に `255.255.255.255` global broadcast を打っていた。multi-tenant subnet (colo / VPS) では WOL magic packet と MAC が neighbor に丸見え |
| ファイル | `shuttlescope/backend/cluster/topology.py` |

**修正方針**: `ipaddress.is_link_local` または `is_private` のみ許可、それ以外 / 解析失敗は WOL refuse。

### R18a-2 P3-2 — dev-mode loopback grant の ENVIRONMENT 厳格化

| | |
| --- | --- |
| 影響 | `is_loopback_request` は `not _is_production_mode()` で blank/testclient を loopback とみなしていたが、staging で `ENVIRONMENT=""` だと「非 production」になり ASGI バグで `client.host=""` の本番外部リクエストが loopback 認定される穴 |
| ファイル | `shuttlescope/backend/utils/control_plane.py` |

**修正方針**: `ENVIRONMENT` が `development`/`dev`/`test`/`testing` のときだけ blank/testclient 許容。

### R18a-1 P3-2 — `_validateUserUrlForCapture` で octal/hex/decimal IPv4 reject

| | |
| --- | --- |
| 影響 | `010.0.0.1` (octal → 8.0.0.1) / `0x7f.0.0.1` / `2130706433` (decimal) を一部 resolver が IPv4 として解決するが、正規表現 `/^10\./` 等は match せず SSRF allow に倒れる |
| ファイル | `shuttlescope/electron/main.ts` (`_validateUserUrlForCapture`) |

**修正方針**: `/^[0-9]/.test(host)` で **数字始まり hostname** を全 reject (キャプチャ対象は legitimate な公開 URL のみなので副作用無し)。

### その他 (詳細省略)

- `install_supervisor.ps1` `>/dev/null` → `>nul`。
- `_FORCED_STRIP_COLUMNS` に MFA / role / is_active / pkid 等を追加。
- `_sweepStaleUploadQueue` の module-level flag。
