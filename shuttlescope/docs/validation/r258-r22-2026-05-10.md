# Round 258 R22 — R20→R21 regression 監査の P0/P1 を一括クローズ

## 概要

R21 (ee3d5cf) を 1 体の独立 agent で再監査。R20→R21 で導入したコードに以下の弱点
を発見:

- **P0**: IPv6 bracket bypass — `_validateUserUrlForCapture` で `[::1]` がバイパスする SSRF
- **P1**: `is_loopback_request` の env 直読が pytest を破壊
- **P1**: 1-year fail-closed が DB outage 時に全ユーザログアウト + DB 連打 cascade
- **P1**: realpath jail が allow-list に prefix match できず legitimate write を sliently 拒否
- **P1**: revoke が no-op username 再送でも発火 self-DoS

すべて R22 で 1 commit クローズ。R22 P2-3 (UploadSession TOCTOU) も同梱。

## 修正一覧

### R22 P0-1 — IPv6 bracket bypass

| | |
| --- | --- |
| 影響 | `new URL('https://[::1]/').hostname` は Node では **`'[::1]'` (角括弧付き)** を返すため、旧コードの `/^::1$/` 等のリテラル比較は完全空振り。攻撃者は `https://[::1]:8765/admin` / `https://[::ffff:127.0.0.1]/` / `https://[fe80::1]/` 等で SSRF guard を抜けて screen-capture / loadURL から内部 IP を叩ける |
| ファイル | `shuttlescope/electron/main.ts` (`_validateUserUrlForCapture`) |

**修正方針**:
- `parsed.hostname.toLowerCase().replace(/^\[|\]$/g, '')` で角括弧を除去してから regex 比較。
- 追加で IPv6 unspecified `::` / multicast `ff..::` / IPv4-mapped `::ffff:` も明示 reject。

### R22 P1-1 — `is_loopback_request` で pytest を loopback 認定しない regression

| | |
| --- | --- |
| 影響 | 旧 R20 実装は `os.environ.get("ENVIRONMENT","")` 直読のため、pytest が ENVIRONMENT を export しない通常 setup では env_norm が "" となり、TestClient (`client.host=="testclient"`) を非 loopback 扱い → 多数の test が 403。さらに本番で env が空に misconfig されると loopback grant が完全に切れて DoS |
| ファイル | `shuttlescope/backend/utils/control_plane.py` |

**修正方針**: `backend.config.settings.ENVIRONMENT` (default "development") を経由する。settings 側で strip+lower 済みのため env が空でも development と解釈される。読込失敗時のみ env 直読に fallback。

### R22 P1-2 — per-user fail-closed が cascade DoS の地雷

| | |
| --- | --- |
| 影響 | R21 実装は DB exception 時に `now + 365*86400` を **キャッシュせず** 返していたため、(1) 全 user が 1 年失効扱いで logout、(2) 毎リクエストで DB 再 hit してスレッドプール飢餓、(3) cache が in-process なので運用 escape hatch なし |
| ファイル | `shuttlescope/backend/utils/jwt_utils.py` |

**修正方針**:
- horizon を 600s (= 10 min) に縮小。DB が 10 分以内に回復すれば auto-heal。
- 戻り値を 2 秒だけ短期 cache (`now - (TTL - 2s)` で書く → 残り 2s)。DB 連打を防ぎ、回復後すぐ通常 path に戻る。

### R22 P1-3 — realpath jail allow-list の prefix match 不一致

| | |
| --- | --- |
| 影響 | `app.getPath('documents')` は Windows folder redirection / D:\ 移動で junction を返す場合があり、realpath された canonical path と allowedRoots が prefix match せず legitimate な保存先 (= ユーザの実 Documents) が silently 拒否される |
| ファイル | `shuttlescope/electron/main.ts` (save-recorded-video) |

**修正方針**:
- `app.getPath()` 戻り値も `fsMod.realpathSync` で canonicalize してから allowedRoots に登録。
- 比較を `path.relative(root, finalReal)` 経由に変更し、結果が `..`・絶対パス・空でない pure descendent のみ inside 扱い (case 比較・sep 一致・prefix bug を回避)。
- 最終 path も再 realpath して basename junction file 経路にも対応。

### R22 P1-4 — `update_user` revoke が no-op で発火 self-DoS

| | |
| --- | --- |
| 影響 | R21 実装は `body.model_dump(exclude_unset=True)` に該当 field が含まれていれば revoke を発火していたため、no-op 同値再送でも tokens 失効 → 自己 DoS / RevokedToken 行数膨張 / log noise |
| ファイル | `shuttlescope/backend/routers/auth.py` (update_user) |

**修正方針**: mutation 開始前に `user.role` / `user.username` / `user.hashed_credential` を snapshot し、commit 後に**実値が変わった場合のみ** revoke を発火する。

### R21 P2-3 — loopback init TOCTOU 同梱

`uploads.py` の lock 定義が R21 では module 不在だったため build error の手前。本 R22 で `_LOOPBACK_INIT_LOCK = threading.Lock()` を module-level 宣言。

### R21 P2-2 — `_validate_url_for_subprocess` getaddrinfo SSRF check

`youtube_live_recorder.py` の URL 検証で hostname を `socket.getaddrinfo` 経由で実 IP に解決し、結果が internal/reserved なら reject する経路を追加。`localhost.attacker.com` 系の DNS-rebind 既知パターンを塞ぐ。

## 検証

### Frontend build
- `NODE_OPTIONS=--max-old-space-size=16384 npm run build` 成功 (electron-vite, ✓ built).

### Backend
- pytest はローカル venv 不在のためスキップ。
- 修正は narrow:
  - control_plane.py: ENVIRONMENT lookup 1 ブロック書き換え。
  - jwt_utils.py: fail-closed 経路 1 ブロック書き換え。
  - electron/main.ts: 2 ブロック (IPv6 bracket / realpath relative)。
  - auth.py: snapshot 3 行追加 + revoke 条件 3 行書き換え。
  - uploads.py: module-level lock 1 行 + 経路の lock 取得 1 ブロック。
  - youtube_live_recorder.py: getaddrinfo loop 追加 1 ブロック。

### Manual (本番デプロイ後)
- `attacktest/round258_r22_ipv6_bracket.py`: `_validateUserUrlForCapture('https://[::1]/admin')` が throw すること。
- `attacktest/round258_r22_db_outage.py`: DB を一時停止 → verify_token が 10 分後に auto-heal すること。
