# Round 258 R24 — R23 audit P0 hotfix + 残 P1/P2

## 概要

R23 (328f1d5) を 1 体の独立 agent で再監査。R23 自身に **column overflow の P0** を
発見し即時 hotfix (3358d33)。その後、agent 報告の P1 4 件と P2 2 件を本 R24 で適用。

- R23.1 (3358d33) hotfix: sentinel jti を compact format (`__ur_<id>_<b36_us>_<6hex>`) に変更し String(36) 制約に収める
- R24 P1: `reset_password` (consume) に IP rate limit 追加 (1h/20)
- R24 P1: `dispatch_benchmark` の `creds=None` silent fallthrough 修正
- R24 P1: `_revoked_tokens_gc_loop` の SQLite busy_timeout を engine event listener で per-checkout に適用
- R24 P1: SFTP `%TEMP%` を SSH 先で runtime resolve (corp policy / roaming profile 対応)
- R24 P2: backup passphrase に character class ≥3/4 を追加 (a-t 単独パターンを排除)
- R24 P2: `password_reset_unknown_email` の email_domain を SHA256 prefix hash に置換 (organization 列挙阻止)
- R22 P2-3: IPv6 worker_ip の WOL 短絡 (R23 漏れ分)

## 修正一覧

### R23.1 P0 hotfix — sentinel jti String(36) overflow

| | |
| --- | --- |
| 影響 | R23 の `__user_revoke_<id>_<isoformat>_<32hex>` は ~75 文字で、`RevokedToken.jti = String(36)` を超過。Postgres では `DataError`、SQLite では silent truncation で random suffix が落ちて IntegrityError race が再発 |
| ファイル | `shuttlescope/backend/utils/jwt_utils.py` |

**修正方針**: 新 format `__ur_<user_id>_<base36_epoch_us>_<6hex>` で 36 文字以内に収め、`_get_user_revoke_timestamp` は新旧両 prefix を parse する後方互換実装に。

### R24 P1 — `reset_password` consume rate limit

| | |
| --- | --- |
| 影響 | 旧コードは `request_reset` (送信側) だけに rate limit があり、`reset_password` (consume 側) は無制限。token min_length=10 で attacker は brute force 可能 |
| ファイル | `shuttlescope/backend/routers/auth_email.py` |

**修正方針**: `_enforce_rate_limit(scope="reset_consume", ip_max=20, ip_window_s=3600, email_max=0)` を追加。

### R24 P1 — `dispatch_benchmark` の `creds=None` silent fallthrough

| | |
| --- | --- |
| 影響 | 全 worker で `_get_worker_ssh_creds` が None を返すと results は空のまま return → UI から「成功 / 失敗」の区別が付かない無音。env 設定漏れの operational bug が見落とされる |
| ファイル | `shuttlescope/backend/cluster/remote_tasks.py` |

**修正方針**: `skipped_no_creds` リストを別途集計し、空 results + skip 有り時は `{"warning": ..., "skipped_no_ssh_creds": [...]}` を返す。

### R24 P1 — SQLite `busy_timeout` を engine event listener で適用

| | |
| --- | --- |
| 影響 | R23 の `_probe.execute("PRAGMA busy_timeout = 5000")` は SQLite PRAGMA が **per-connection** で別 connection を取り出す `cleanup_expired_revoked_tokens` には反映されず no-op だった |
| ファイル | `shuttlescope/backend/main.py` (lifespan) |

**修正方針**: `sqlalchemy.event.listens_for(engine, "connect")` で全 connection に PRAGMA を強制。1 度の listener 登録で全 SessionLocal に反映。

### R24 P1 — SFTP `%TEMP%` runtime resolve

| | |
| --- | --- |
| 影響 | `C:/Users/{username}/AppData/Local/Temp/` を hard-code すると、worker user の `%TEMP%` がリダイレクトされている (corp policy / roaming profile) 場合に書込先と実 path が乖離。R23 の TOCTOU 緩和が空振りする |
| ファイル | `shuttlescope/backend/cluster/remote_tasks.py` (`_ssh_run_python_script`) |

**修正方針**: SSH 接続後に `cmd /c echo %TEMP%` を投げ、実 path を resolve してから `<resolved>/ShuttleScope/ss_task_<32hex>.py` に書く。失敗時は default fallback。

### R24 P2 — backup passphrase character class ≥3 of 4

| | |
| --- | --- |
| 影響 | Shannon ≥4.0 単独だと `"abcdefghijklmnopqrst"` (a-t 20 chars unique) が log2(20)≈4.32 で通るが、26-letter 辞書攻撃の射程内 |
| ファイル | `shuttlescope/backend/services/backup_service.py` |

**修正方針**: 大文字 / 小文字 / 数字 / 記号 の 4 種から 3 種以上を含めることを必須化。`secrets.token_urlsafe(24)` は自動で複数 class を含むので影響なし。

### R24 P2 — `password_reset_unknown_email` の domain 平文 logging

| | |
| --- | --- |
| 影響 | 旧コードは `email_domain` を平文でログ → access_log 読取り権限の analyst が 429 + domain 観測で組織 domain の user 列挙を実施可能 |
| ファイル | `shuttlescope/backend/routers/auth_email.py` |

**修正方針**: `email_domain` を SHA256 hexdigest の先頭 8 hex に置換。同 domain 判定は可能だが平文露出は防ぐ。

### R22 P2-3 同梱 — IPv6 worker_ip WOL 短絡

`wake_worker` で `IPv6Address` の場合は WOL refuse (IPv4 broadcast 前提のため)。
