# Validation: Triton-on-Windows + torch.compile for SAM3 decoder

Date: 2026-05-30
Branch: feat/sam3-triton (worktree wt-sam3-triton)

## Change
Installed `triton-windows==3.5.1.post24` into the production backend venv (additive only;
torch untouched) to unlock inductor/Triton codegen for `torch.compile` on Windows + RTX 5060 Ti
(sm_120) + torch 2.11.0+cu128. Added profiling scripts to `tools/sam3_profile/`.

## What was validated
1. Triton imports (3.5.1) and a `@triton.jit` kernel runs correctly on the GPU (max err 0.0).
2. Inductor smoke test compiles + runs correctly (max err 4.8e-7); MSVC wrapper compile works.
3. SAM3 decoder-only `torch.compile(dynamic=True)` (inductor default, no cudagraphs):
   eager 181.39 ms -> compiled 168.10 ms (1.079x e2e), 0 recompiles,
   mask IoU mean 0.9999 / min 0.9996 vs eager.

## What does NOT work (documented, not used)
- mode=reduce-overhead (cudagraphs): tensor-overwrite hazard in backbone neck conv2d.
- backbone+decoder max-autotune: recompile-thrash on SAM3 dynamic shapes (re-autotunes per call).

## Production impact
No production code path changed. Only additive package install + experiment scripts on the
feature branch. The decoder-only compile is a candidate optimization, not yet wired into the
serving path. torch + CUDA verified healthy in the backend venv after the triton-windows install.
